## Brand and product constraints

Warm white, coral, lilac, sage and ink; Manrope and IBM Plex Mono. Preserve the bracket-and-point logo, Sample workspace and Sign in in navigation. Avoid decorative background lines, particles, abstract AI orbs, invented results and customer claims. Keep the headline and workshop action visible before any interaction. Source clauses and decisions must remain readable HTML when built.

Use the existing fictional Atlas Reference fixture. External inference requires counsel and returns no output. The product must not imply that reading access authorizes every downstream use or that the website grants real data access.

## Clause Window

A large coral sculptural aperture anchors the right side of an editorial cream hero. One source sheet passes through it and a decision slip appears alongside the source basis. This makes the existing bracket logo into a tangible brand object.

Scroll sequence: source approaches the aperture; intended use changes to external inference; the decision slip emerges with Requires counsel and the clause reference. Reverse scrolling reverses the physical sequence. Three chapter controls jump to the same states. A short user-initiated playback can demonstrate the sequence and be paused.

Use layered geometry and live HTML rather than a flattened screenshot for the interactive object. Keep subtle perspective changes local to the object. On mobile, remove pinning and present the source, use and decision as a compact step selector.

## Living Rights Desk

An editorial masthead sits above a broad open folio. The left page carries the source clause; the right page contains intended use, destination and result. It offers the most direct hands-on explanation of the product.

Scroll sequence: the folio opens slightly; the source clause is highlighted; the result resolves. Visitors can choose Read, Embed or Inference and Internal or External model. Each choice updates the cited basis and decision from the existing approved synthetic fixture, with text and icons as well as color. Hover lifts a page corner; clicking the basis exposes the relevant excerpt.

Build the page content as semantic text and native controls with a restrained layered paper treatment. Do not use generated small-print prose as authoritative license content. On mobile, switch to a vertical document/use layout with the same controls.

## Evidence Reel

An ink stage contrasts with the light site navigation. Large typography introduces three physical objects: source, intended use and receipt. The central object changes as the visitor scrubs the sequence.

Scroll sequence: source takes focus, then the request advances to the foreground, then the receipt reveals the decision and basis. Chapter buttons provide a keyboard-accessible alternative. A destination selector changes the request and receipt together. Reverse scrolling returns to earlier states.

Use a short desktop GSAP sequence, with restrained rotation and depth. Preserve legibility by keeping the active object's text upright. Mobile uses a single active object and native chapter buttons.

## Motion implementation requirements after selection

- One sequence driven by GSAP ScrollTrigger and integrated with the existing Lenis instance.
- Keep homepage motion bespoke; do not apply the separate-page alternating lateral reveal to this hero.
- Treat click, keyboard and scroll as equivalent ways to inspect the same story.
- Short desktop pin only if needed; no forced scroll hijacking.
- With reduced motion, show the complete readable state and retain all controls without spatial animation.
- No mandatory autoplay. If playback is added, expose Pause and stop it when the hero is offscreen.
- Avoid layout shifts. Animate transforms and opacity while reserving object dimensions.
- Never animate the actual pinned container; animate its children.
- Scope and clean up timelines on route changes.
- Verify desktop/tablet/mobile navigation alignment, keyboard controls, reverse scrolling, reduced motion and canonical decisions before replacing the current hero.
